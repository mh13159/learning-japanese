## What changed in this work block

### Architecture: removed all hardcoded translation tables
- Deleted `lib/seed-translations.ts` entirely.
- `lib/translate.ts` now delegates EN↔JA to:
  - **Jisho.org public JSON API** (community-run, free, JMdict-backed) for short queries (1–3 tokens).
  - **Self-hosted LibreTranslate** (Docker container, AGPLv3) for sentences and dictionary misses, via `LIBRETRANSLATE_URL` env var.

### New file: `lib/dictionary.ts`
- `lookupEnglishWord(en)` and `lookupJapaneseWord(ja)` — single-word/short-phrase JMdict lookups via `https://jisho.org/api/v1/search/words`. 6-second timeout, 1000-entry in-memory cache, gloss-match validation guards against loose results.
- `isLikelyDictionaryQuery(text)` — `length(words) ∈ [1, 3]`.
- `disambiguateAsciiInput(text)` — async tiebreaker. For inputs the sync heuristic flagged as `"ambiguous"`, this asks Jisho whether the literal string appears as an English gloss (→ english) or as a Japanese reading on a common+JLPT-tagged entry (→ romaji).

### Detection rewrite
`detectInputType()` retained for callers; new `detectSync()` returns `english | romaji | japanese | ambiguous`. `translate()` awaits the tiebreaker when sync returns `ambiguous`.

Removed brittle patterns from the Japanese phonotactic regex: `ou`, `ei`, `aa`, `ii`, `uu` overlap with English words. Added English-only digraphs (`rr`, `ll`, `ff`, `mm`, `dd`, `ww`, `bb`, `ee`, `oo`) as fast-path English markers — these never occur in romaji.

### Romaji orthography fix (rule-based, no tables)
`fixRomajiParticleKana()` in `lib/translate.ts` restores the particle exceptions wanakana doesn't apply: `wa→は` for topic-marker contexts (incl. the greeting suffixes `konnichiwa`/`konbanwa`), `o→を` for object-marker, `e→へ` for direction-marker. Pure pattern matching against the original romaji string, no per-word translation lookup.

### Infra
- LibreTranslate v1.9.5 running in WSL Docker as container `libretranslate`. Image: `libretranslate/libretranslate:latest` (599 MB on disk). Started with `--load-only en,ja`. Bound to `0.0.0.0:5000`.
- `japanese-translator/.env.local` created with `LIBRETRANSLATE_URL=http://localhost:5000`. Gitignored.
- `.env.local.example` rewritten to reflect FOSS-only config (LibreTranslate URL only, no commercial API keys).
- README top-half rewritten: drops the "agentic AI framework" claims, documents the open-source stack, lists Docker quick-start and Python quick-start for LibreTranslate.

## Known remaining quality issues (not blockers)

1. **`inu` → 戌 instead of 犬.** Jisho's `pickBestEntry` returns the first common entry, which for the keyword "inu" puts the Chinese-zodiac-dog kanji ahead of the standard "dog" kanji. Acceptable — the gloss includes "dog" — but a real-world Japanese speaker would expect 犬. Potential fix: prefer entries whose first sense's first definition is the shortest/most-common gloss. Deferred.
2. **`me` → お問い合わせ via LibreTranslate.** Jisho can't pin down the pronoun (likely matches 目 first, validation rejects, falls through). LibreTranslate's small Argos model hallucinates "inquiry". Pronouns are inherently context-dependent in Japanese (私/僕/俺); no single right answer. Deferred.
3. **`thank you` → どうも instead of ありがとう.** Both are correct; どうも is more casual, ありがとう is the canonical learner answer. Jisho ranks どうも as the first common match. Could be fixed by adding a "prefer longer/more-formal gloss" rule. Deferred.
4. **`where is the station` → 駅の場所 (literally "station's place").** LibreTranslate's Argos model is weaker than expected on copular questions. Better translation: 駅はどこですか. Could be improved by a different/larger Argos package. Deferred.
5. **LibreTranslate produces transliterations for short proper nouns/concept words.** E.g. `i love japan` → 私は日本を愛する is good, but other short English phrases sometimes come back as katakana transliterations. This is a known limitation of the OPUS-MT-derived Argos model. A larger model package would help.
